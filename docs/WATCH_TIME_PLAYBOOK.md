# Watch-Time Playbook

The system treats **watch time as an editorial design problem**, not a trick.

The objective is not to manipulate viewers into staying. The objective is to
make every section earn the next section.

## The metrics to care about after publishing

Track these in YouTube Analytics:

- **Audience retention curve**
- **Average view duration**
- **Average percentage viewed**
- **First-30-second retention**
- **Key moments for audience retention**
- **Relative retention** when available
- **End-screen / next-video continuation**

There is no universal "good" number across every niche and video length. Use
your own channel baseline and compare each new episode against your previous
videos.

## Pre-publish Retention Lab

Proof of Origin Studio scores five editorial dimensions before rendering:

1. **Hook**
   - Is the question concrete?
   - Is the object visible?
   - Is the controlled change obvious?
   - Does the viewer understand the stakes quickly?

2. **Pacing**
   - Are scenes too long?
   - Is there too much uninterrupted explanation?
   - Are there visual resets?

3. **Proof density**
   - How often does the viewer see evidence?
   - Screenshots
   - before/after changes
   - measured scores
   - verification receipts
   - actual test outcomes

4. **Curiosity**
   - Is there an unanswered question pulling the viewer forward?
   - Does each section create a reason to see the next one?

5. **Clarity**
   - Is the narration concise?
   - Are technical ideas translated into visible examples?

## The first 30 seconds

Recommended structure:

### 0–5 sec
Show the most interesting object or alteration.

Example:

> "This receipt originally said $74.34. I changed it to $70.00."

### 5–12 sec
State the verification question.

> "Could someone who received only the altered document discover the change?"

### 12–22 sec
Show the stakes.

> "The document still looks almost identical."

### 22–30 sec
Open the loop.

> "I ran it through HPS. The first result was not what I expected."

Then move directly into the experiment.

Do not use a long animated logo intro.

## Retention beats

A long-form video should deliberately contain attention events:

- Hook
- Open loop
- Pattern interrupt
- Visible proof
- Explanation reset
- Payoff
- New unresolved question

The Studio maps these on a timeline.

## Pattern interrupts for this channel

Use changes that add information:

- document zoom
- before → after value animation
- screenshot reveal
- confidence meter
- SHA-256 comparison
- redline / deletion visualization
- timeline
- side-by-side source vs candidate
- full-screen one-sentence principle
- brief on-screen question
- diagram transition

Avoid random flashy edits that do not help understanding.

## Proof cadence

Technical channels lose viewers when narration becomes abstract.

A useful internal rule:

> If you have been explaining for too long without showing evidence, put proof on screen.

For HPS videos, strong proof objects include:

- HPS result cards
- record IDs
- exact values changed
- screenshots
- observed confidence scores
- canonical hash mismatch
- signature status
- actual derivative recognition
- failure / inconclusive results

## Open loops

Good:

> "HPS knew the file was related. But could it tell which amount changed?"

Weak:

> "Keep watching to find out."

The open loop should name the unanswered technical question.

## Mid-video resets

At every major section change, change one of:

- camera/visual scale
- layout
- visual grammar
- evidence type
- question

Do not reset with meaningless motion.

## Payoff standard

The promised answer must be delivered clearly before the CTA.

Bad:

> "So that was the test. Subscribe."

Good:

> "$74.34 became $70.00. HPS identified the candidate as related, and the content-integrity layer isolated the changed payment field. That is the answer to the experiment."

Then give the limitation.

## Ending for continuation

End by opening the next genuine experiment:

> "Changing a number is one thing. Next I want to photograph the altered document and see whether the same provenance trail survives."

This creates series-level watch time, not only single-video retention.

## After publishing: feedback loop

For each video, log:

- timestamp of sharp retention drops
- timestamp of spikes / rewatches
- first 30-second performance
- average percentage viewed
- average view duration
- CTR
- comments asking for next experiments

Then tag likely causes:

- intro too long
- title/thumbnail mismatch
- proof arrived too late
- explanation too abstract
- scene too static
- payoff too early
- payoff too weak
- viewers wanted more detail

Use the next video to test one editorial change at a time.
